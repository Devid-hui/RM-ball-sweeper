# OpenRF1 V2.2 点动和采球固件

## 2026-11-26 架空单轮实测

ROCK 4D 经 CH340 USB 转 TTL 模块接到 OpenRF1 的 MV 口（USART2），串口参数为 115200、8N1、无流控。本次使用板上支持 `$Car` 的固件。ROCK 4D 在 7.1.3 内核下通过 `libusb` 访问 CH340。

四轮架空后，按 A、B、C、D 顺序逐路发送 `0.1 m/s` 的目标轮速，其余目标置零。每路持续约 3 秒，随后发送 `$Car:0,0,0,0!`。每路的转动和归零指令都收到 `cmdOk`，现场观察到的轮位如下。

| OpenRF1 通道 | 转动的轮子 | 测试指令 |
| --- | --- | --- |
| A | 前左 | `$Car:0.1,0,0,0!` |
| B | 前右 | `$Car:0,0.1,0,0!` |
| C | 后左 | `$Car:0,0,0.1,0!` |
| D | 后右 | `$Car:0,0,0,0.1!` |

本次 A、C 的轮位与 11 月 25 日原接线记录互换。该表记录驱动通道对应的实际轮位。接入 `COLLECT1` 前，还需逐轮核对编码器通道、计数方向和驱动极性，并让上层轮速重排及反馈映射与现接线一致。

## C26 V2.2 编码器反馈补丁

[补丁](c26-encoder-feedback.patch) 适用于控制板指南解压目录中的 C26 V2.2 工程。它复用厂商 PID 每 20 ms 读取的编码器增量，并通过 MV 口返回累计计数。保留原版 HEX 供恢复。在 C26 源码副本的根目录执行以下命令，将路径替换为补丁的绝对路径。

```bash
git apply --check --ignore-space-change /path/to/c26-encoder-feedback.patch
git apply --ignore-space-change /path/to/c26-encoder-feedback.patch
```

在 Windows Keil 用工程原配 ARMCC 5.06 打开 `Project/RVMDK（uv5）/BH-STM32.uvprojx`，构建产物为 `Output/c26_feedback.hex`。候选补丁已做本地应用校验，Keil 构建和上板验证待做。该版本只增加查询功能，断联停车仍待实测和处理。

烧录候选版本后，用 115200、8N1 连接 OpenRF1 的 MV 口，从项目根目录运行以下命令。普通串口路径使用 pyserial。ROCK 4D 上如使用 PyUSB 访问同一 CH340，端口参数填 `ch340`。

```bash
python3 tools/check_openrf1_uart.py --port /dev/cu.usbserial-XXXX --c26-encoders 20
```

查询只发 `$ENC!`，回复为 `ENC <sample> <A> <B> <C> <D>` 加 CRLF，五个字段均为无符号 32 位。首条只有计数，后续用相邻回复的计数差和 MCU 采样间隔计算 `rpm_abcd`。静止时四路转速应为零，逐轮转动时观察通道和正负号。默认按每个输出轮圈 4680 个计数换算，可用 `--counts-per-rev` 覆盖。

## 点动与采球固件协议

适用于 STM32F103RCT6。复位后等待串口命令。板载 USB-TTL（USART1）和 ROCK 4D 所接的 MV 口（USART2）均为 115200、8N1、无流控。每条命令以 LF 结束，支持 CRLF。点动固件 `openrf1_wheel_jog` 将回复发到两个串口，测试时使用一个发送端。

| 命令 | 回复及行为 |
| --- | --- |
| `PING` | `PONG` |
| `ENC` | 四路原始 16 位计数，例如 `A=0 B=0 C=0 D=0`；读数可在 0 和 65535 之间回绕 |
| `JOG C`（A、B、D 同理） | 对所选驱动通道输出正向 PWM，20% 占空比，约 0.2 秒后返回 `DONE`。同一通道每次复位只执行一次，重复请求返回 `ALREADY` |

下表是 2026-11-24 至 25 日原接线下的历史手转记录。增量符号以车轮向前滚动为准。

| 轮位 | 前左 | 前右 | 后左 | 后右 |
| --- | --- | --- | --- | --- |
| 编码器通道 | C | B | A | D |
| 向前时原始增量 | − | + | − | + |

点动前需架稳车身使四轮离地，移开手和线束，为电机驱动接入匹配的主电源。对本车额定 6 V 的 TT 马达，选用极性正确的 6 V 稳压主电源，按控制板手册选取至少 5 A 的供电能力。USB 可用于下载和查询编码器。

采球入口使用同目录构建的 `openrf1_collector.hex`。该版本在收到请求的串口回复，`VER` 返回 `COLLECT1`。两口都可使用 `PING`、`ENC`、`STOP`，带 CRC 的轮向配置 `D` 和四轮指令 `W` 仅在 ROCK 所接的 USART2 生效。轮速单位为每 20 ms 的千分之一编码器计数，按 A/B/C/D 排列。每条 `W` 回复包含序号和四个原始计数。命令中断 500 ms 后控制循环清零，控制周期为 20 ms。实车先用点动固件测量轮向，再用采球固件运行闭环。

## 四轮架空点动记录

2026-11-24 至 25 日，电脑经 CH340 登录 ROCK 4D，从板上 `/dev/ttyS4` 查询 OpenRF1。`PING` 返回 `PONG`，`VER` 返回 `ERR`，`ENC` 能读到四路计数，符合点动固件的协议。每路单独点动一次，表内是扣除 16 位回绕后的原始计数差。

| 点动通道 | 固件回复 | ΔA | ΔB | ΔC | ΔD |
| --- | --- | ---: | ---: | ---: | ---: |
| A（后左） | `DONE` | 0 | 0 | 0 | 0 |
| B（前右） | `DONE` | 0 | −1 | 0 | 0 |
| C（前左） | `DONE` | 0 | 0 | +1 | 0 |
| D（后右） | `DONE` | 0 | +1 | 0 | 0 |

四次点动后连续三次静止读数均为 `A=0 B=1 C=1 D=0`。四个目标通道均未达到检查工具的 3 计数门槛，驱动轮位和正命令的实际转向仍待验证。先在停机状态给输出轮做标记，向车头方向手转一整圈，读取对应通道的计数差。再核对驱动主电源和线束，复位后用同样的短脉冲对照观察轮位和计数。

## 构建与烧录

从仓库根目录执行，需要 CMake 3.20+、Ninja 和 GNU Arm Embedded 工具链（实测 GCC 14.2.1）。

```sh
cmake -S firmware/openrf1 -B build-openrf1 -G Ninja
cmake --build build-openrf1
cmp build-openrf1/openrf1_wheel_jog.hex firmware/openrf1/release/openrf1_wheel_jog.hex
```

[可供 FlyMcu 写入的 HEX](release/openrf1_wheel_jog.hex) 对应 2026-11-24 至 25 日点动试验使用的版本。使用 OpenRF1 白色 USB-TTL 对应端口，在 FlyMcu 选择“RTS的高电平复位,DTR低电平进BootLoader”，使用已验证的 9600 下载速率并启用写后校验。烧录会替换板上原程序。应用启动后切换至 115200 发送 PING 和 ENC。

启动代码、链接脚本、CMSIS 和标准外设库来自 ROCK4D_OpenRF1_通信配置指南_20261122 配套工程，第三方文件保留原版权声明。四路引脚映射依据厂家 C25 v5 电机例程。


## 2026-11-25 架空复测与 A 口排查

复测时四轮悬空。通过板载 USB-TTL 使用限时点动，每次只测试一个控制输出。下表记录原接线下的轮位和 16 位编码器净增量，保留编码器原始正负号。

| 接口 | 原接线轮位 | 点动输出 | 编码器净增量 | 结果 |
| --- | --- | --- | ---: | --- |
| A | 后左 | `PC10`、`PA12` 两个候选脚分别点动 | 0、0 | 未通过 |
| B | 前右 | `PC9` | -1906 | 转动并停稳 |
| C | 前左 | `PC6` | +1510 | 转动并停稳 |
| D | 后右 | `PA8` | +1938 | 转动并停稳 |

B、C、D 每次点动时其余三路编码器增量均为 0。当时上层轮速顺序为前左、前右、后左、后右，对应串口通道 `C、B、A、D`。该轮原接线单轮驱动通过 3/4，四轮同转和地面运动当时均待验收。

### 左轮换接对照

整组互换 A、C 的六芯插头。电机主电源关闭时手转后左，只有 C 变动 -1807。手转前左，只有 A 变动 -2331。接通同一主电源后，后左接 C 实际转动，C 增加 +1750。前左接 A 时现场未见转动，两个候选输出点动均为 0。两只左轮的马达连同各自线束在 C 口均有实际转动记录。

### 原厂控制脚复测

厂家原理图和霍尔电机例程 `MOTOR_A_SetSpeed` 将 A 通道配到 `PC7`（`TIM8_CH2`）和 `PA11`。恢复原接线后，分别以 40% 占空比点动约 240 ms，现场确认了下表的实际轮位。

| 点动 GPIO | 实际转动 | ΔA | ΔB | ΔC | ΔD |
| --- | --- | ---: | ---: | ---: | ---: |
| `PC7` | 前左（C） | 0 | 0 | -1456 | 0 |
| `PA11` | 后右（D） | 0 | 0 | 0 | -2001 |

### 故障范围和待查项

- 当时原厂 A 控制脚配置与实测轮位错配，A 驱动输入及 PCB 版次待核对。
- 按厂家原理图，编码器 A 对应 `CN2`。两根马达动力线为 `CN2-1` 至 `U3`（`AT8236`）8 脚 `OUT2`，以及 `CN2-6` 至 `U3` 6 脚 `OUT1`。板端待排查项包括插座接触、焊点、输出走线和驱动芯片。
- 本轮缺少板端通断及驱动波形测量。断开主电源和 USB 后，先核对 `CN2-1`、`CN2-6` 在实板上分别通到哪颗驱动芯片的输出，再从该芯片反查两个控制输入。测试结束时已恢复原接线并关闭电机电源。
